# HexWave Radio

![Логотип HexWave Radio](assets/hexwave-logo.png)

**Autonomous AI Radio Station** — автономная радиостанция для Discord. Шесть ведущих создают общий эфир: Луна, Сол, Грок, Дип, Глим и Клод. Слушатели в подключённых голосовых каналах слышат одну и ту же программу. Слушатель может предложить трек или написать в студию, но решение о выпуске остаётся за редакцией станции; обычной кнопки пропуска нет.

Статус: **публичная бета исходного кода**. Короткие тесты эфира пройдены, но длительные проверки непрерывности, ресурсов и работы в нескольких серверах ещё не завершены. Бета-релиз не означает готовность к круглосуточному производственному запуску или публичному вещанию музыки.

## Как устроен эфир

- **Ведущие** говорят от своего имени и озвучиваются разными голосами RHVoice. Их смены и музыкальный план организует постоянная Луна «за кулисами». Она управляет программой и не заменяет текущего ведущего в эфире.
- **Общая волна** — одна последовательность треков и реплик для не более чем трёх Discord-серверов. Только директор станции меняет порядок воспроизведения; SQLite сохраняет его и принятые обращения слушателей.
- Музыка выбирается из плана Луны и проверяется через каталог YouTube Music или, при отдельной настройке, Spotify. Медиа заранее готовится в ограниченном локальном кеше. Произвольные ссылки и файлы слушателей не ставятся в эфир.
- Реплики и планы запрашиваются через **Tooken Club** с его собственным ключом и OpenAI-совместимым интерфейсом. Прямой ключ OpenAI не используется. Если генерация или озвучка реплики не успела, музыка не ждёт её. Если планирование недоступно и подготовленные по прежнему плану песни закончились, станция сообщает об ухудшении работы; случайную музыку она не подставляет.

Команды для слушателя: `/request`, `/studio`, `/radio now`, `/radio status`, `/radio mine`, подключение и отключение бота в своём голосовом канале. Владелец станции и назначенные им администраторы управляют эфиром и аварийным пропуском. Роль администратора Discord сама по себе этих прав не даёт. Подробные правила — в [спецификации](docs/product/radio-spec.md), этапы развития — в [дорожной карте](docs/product/roadmap.md).

## Локальный запуск для тестирования

Нужны Docker Compose, отдельное тестовое Discord-приложение и сервер. Файл `deploy/discord-radio/.env` содержит секреты и не должен попадать в Git. Не используйте реальные ключи в issue, логах или примерах документации.

1. Скопируйте [пример конфигурации](deploy/discord-radio/.env.example) в `deploy/discord-radio/.env`. Укажите `DISCORD_TOKEN`, `DISCORD_CLIENT_ID`, один Discord ID владельца в `DISCORD_OWNER_IDS` и `RADIO_STATION_NAME=HexWave Radio`. Для редакционного музыкального плана укажите `TOOKEN_API_KEY`; `OPENAI_BASE_URL` должен указывать на `https://tooken.club/v1`. Не помещайте сюда ключ проекта OpenAI.
2. Базовый Compose-стек запускает радио и `ytaudio` для YouTube Music. Для голосов RHVoice включите профиль `tts` и задайте `TTS_BASE_URL=http://tts:8092` в `.env`. Профиль Spotify требует отдельной авторизации, Spotify Premium и настройки `spotify-shim`; он необязателен для первого теста.
3. Из корня репозитория запустите:

   ```bash
   docker compose -f deploy/discord-radio/docker-compose.yml --env-file deploy/discord-radio/.env --profile tts build radio ytaudio tts
   docker compose -f deploy/discord-radio/docker-compose.yml --env-file deploy/discord-radio/.env --profile tts up -d
   ```

   На Docker Desktop для Windows добавьте `-f deploy/discord-radio/docker-compose.windows.yml` к обеим командам. Этот вариант хранит SQLite и WAL в томе Docker.
4. Проверьте `http://127.0.0.1:9380/health`, затем `/radio status` и `/radio health` в тестовом сервере. В нужном голосовом канале выполните `/radio join` от имени владельца и послушайте реальный эфир. HTTP health сам по себе не подтверждает слышимый звук.

Практические проверки, восстановление и ограничения тестового запуска описаны в [runbook](docs/operations/runbook.md). Для проверки исходников нужны Node.js 26+ и pnpm: `pnpm --filter @hexwave/radio test`, `typecheck`, `build`.

Исходный код DeadAir распространяется по [MIT](LICENSE); используемые контейнеры, движок и наборы голосов могут иметь собственные условия. Репозиторий и подписка на музыкальный сервис **не дают прав на распространение или публичное воспроизведение музыки**. Перед любым публичным вещанием оператор должен отдельно проверить права на композиции, записи, источники медиа и выбранные голоса. Текущий тестовый эфир не является разрешением на публичную ретрансляцию.
